# STM32 学习站实施路线

每批修改前先读 [课程与速查编写规范](content-style.md)，交付时按其中的页面和示例验收项检查。

## 当前速查交付顺序

站点现以寄存器、SPL 和题库为入口。[芯片覆盖清单](../src/content/docs/coverage.mdx)记录每个模块的适用范围与完成状态。每批验收包括生产构建、搜索、锚点、中文手册页码和 C 示例编译。真板现象单独记录。

1. 首页、导航、速查布局和既有题目迁移已落地。
2. 修订 ADC1/2 与 DMA1 的初始化、配对读取及错误恢复，逐项核对芯片适用性和示例。
3. 连续补齐 I²C/SPI、RTC/BKP/PWR 与看门狗、Flash/启动/UID/CRC、USB FS Device/bxCAN。每组完成后执行本地检查并继续，真板状态单独登记。

## 原教学路线存档

从 STM32F103C8T6 的完整资源清单拆分交付。每完成一批，更新覆盖清单、交付该批课程和实验，等使用者验收后再开始下一批。表中的项目用于综合练习，各模块的工作模式和验证任务以需求文档的覆盖清单为准。

| 阶段 | 交付 | 验收方法 |
| --- | --- | --- |
| 1. 需求与阶段路线 | 全芯片覆盖清单、模块交付标准、项目和阶段路线 | 确认芯片资源覆盖、学习深度、实验顺序和最终验收方式。 |
| 2. 创建站点并完成样章 | Astro + Starlight 项目、启动说明、RCC + GPIO 样章、速查、课后题和两份完整实验工程 | 本地可启动，生产构建及两份固件编译通过。能搜到 `RCC_APB2ENR`、`GPIO_Init`、`CNF13` 和“开漏”，并沿链接找到含义、依据和实验。抽查 GPIO 条目、做题后展开答案。使用者按说明上板完成两种写法及漏开时钟排故。 |
| 3. 时钟、中断与调试 | RCC 完整时钟树、AFIO、EXTI、Cortex-M3、SysTick 与调试、按键切换 LED 模式 | 核对时钟与复用，验证按键消抖、中断优先级，借助调试器定位预设故障。 |
| 4. 定时器与串口 | TIM1、TIM2/3/4、USART1/2/3，串口 PWM 调光及反应计时器 | 测量 PWM 和捕获结果，验证串口错误输入。反应计时器覆盖正常、抢跑、超时和多轮场景。 |
| 5. 采样与搬运 | ADC1/2、内部通道、DMA1，周期采集项目 | 验证触发频率、缓冲区半满和满传输，以及数据和错误的处理。 |
| 6. 板级串行总线 | I²C1/2、SPI1/2，分别与器件或对端通信 | 能读波形，验证 I²C 应答与超时，以及 SPI 模式和片选。 |
| 7. 供电、时间与恢复 | RTC、BKP、PWR、IWDG、WWDG | 验证报警唤醒、备份数据保留、看门狗复位原因和恢复路径。 |
| 8. 存储与校验 | Flash、SRAM、启动模式、选项字节、CRC、UID | 验证 Flash 读回与 CRC 结果，解释启动与存储布局。 |
| 9. USB 与 CAN | USB FS Device 和 bxCAN，分别安排设备枚举与 CAN 通信 | 验证 USB 枚举和数据交换、CAN 回环与对端通信，并说明共享资源约束。 |
| 10. 独立综合验收 | 采集与记录终端任务书、测试用例、故障和变更要求 | 按需求独立选外设，交付资源分配和数据流，通过正常、异常和复位恢复用例，再独立完成一次变更。逐项复核所有外设课程和实验的验收状态。 |
| 11. HAL 与 FreeRTOS | 先做 HAL 迁移，再做 FreeRTOS 进阶路线，两者分别验收 | 迁移后重跑同一套行为测试。RTOS 阶段验证任务通信、调度行为和故障定位。 |

## 阶段 2 的执行顺序

1. 创建站点和本地启动说明，搭好学习、速查、项目三个入口。
2. 编写 RCC + GPIO 课程、GPIO 简图、寄存器和 SPL 索引，打通双向链接。
3. 每个知识点编写约三道课后题并记录出处。补齐寄存器版和 SPL 版实验工程、接线和构建说明，以及漏开时钟的故障场景。
4. 运行网站生产构建和两份固件的编译，在浏览器中检查四个搜索词、条目跳转和答案展开。提供接线、输出行为与排故步骤的清单，由使用者在自己的板卡上验收。

阶段 2 开始时再把这些工作拆成具体文件和验证命令。每批开工前确认板卡和外接器件条件，区分能用当前设备验证的项目和待补齐的真板验收项。HAL 与 FreeRTOS 的详细实施计划放在裸机综合验收之后制定。
